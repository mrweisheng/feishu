# 知识库管理页部署指南(knowledge.eazycar.top)

> 面向运维:从拉代码到公网可访问的完整步骤。域名 DNS 已解析到本服务器,剩下就这三件事:
> **服务起来 → Nginx 反代 → HTTPS**。全程不需要在云安全组开任何新端口(80/443 已为其他项目开放)。

## 架构一览

```
同事浏览器 ──HTTPS:443──▶ Nginx ──HTTP──▶ 127.0.0.1:4111(本服务,Hono)
                              │                │
                              │ 只放行:         ├─ /admin            管理页(登录界面)
                              │  /admin         ├─ /api/knowledge/*  知识库 API(登录鉴权)
                              │  /api/knowledge │  └─ 其余路径 404(messages/客资/Mastra 不出网)
                              │                 │
飞书 ◀────出站长连接(WS)─────────────────────────┘ 群问答/知识库检索不依赖任何入站端口
```

**鉴权**:预设账号登录 `shengwei / 123456`,无需任何配置。会话为 HttpOnly cookie,7 天有效;
登录连错 5 次按 IP 锁 2 分钟。(想换账号口令时在 `server/.env` 配 `KB_ADMIN_USER` / `KB_ADMIN_PASSWORD` 即可,改完重启生效)

## 一、部署服务

```bash
cd /path/to/feishu/server
npm ci

# .env 检查清单(其他变量沿用现有部署,只关注这几项):
#   HOST            保持默认 127.0.0.1(Nginx 同机转发,不要 0.0.0.0)
#   PORT            默认 4111,如与现有服务冲突可改,Nginx 配置同步改
#   EMBEDDING_API_KEY  硅基流动 API Key(向量检索用;不配则知识库降级为纯关键词检索)
# 登录账号无需配置:预设 shengwei / 123456

npm run build && npm start
# 启动日志确认这几行:
#   ✅ sqlite-vec 已加载: v0.1.9
#   ✅ 嵌入模型自检通过:BAAI/bge-m3 · 1024 维(没配 KEY 则是降级告警,功能仍可用)
#   ✅ HTTP 服务监听 http://127.0.0.1:4111
```

进程守护按你现有方式(pm2 / systemd / docker 随意),**保持单实例**即可(项目硬约束:飞书长连接 + 提醒调度器不允许多实例)。

本机自检:`curl -i http://127.0.0.1:4111/api/knowledge/stats` 应返回 **401 未登录**(这是对的,说明鉴权生效)。

## 二、Nginx 反代

```bash
cp deploy/nginx-knowledge.conf /etc/nginx/conf.d/knowledge.conf
# Debian/Ubuntu 用 sites-available 的:
#   cp deploy/nginx-knowledge.conf /etc/nginx/sites-available/knowledge
#   ln -s /etc/nginx/sites-available/knowledge /etc/nginx/sites-enabled/

nginx -t && nginx -s reload
```

配置文件要点(已写好,这里解释为什么,方便日后改动):

| 配置 | 原因 |
|---|---|
| 只反代 `/admin` 和 `/api/knowledge/` | 管理页是相对路径请求 `/api/knowledge/*`,缺一条就白屏;其余路径 404 是**刻意的**——同进程的 `/api/messages`(全部群聊)、`/api/customer-leads`(全部客资)没有鉴权,不能跟着出公网 |
| `X-Real-IP` 必传 | 服务的登录限流按这个头识别来源 IP,不传则所有失败计入同一桶,一人爆破全员锁 |
| `proxy_read_timeout 60s` | 录入长文触发批量嵌入、检索偶发偏慢 |
| 不要配 WebSocket 相关 | 飞书长连接是**出站**的,不经 Nginx |

## 四、验收

按顺序在本地电脑执行:

```bash
# 1. 未登录访问 API → 401(正确)
curl -i https://knowledge.eazycar.top/api/knowledge/stats

# 2. 错口令 → 401
curl -i -X POST https://knowledge.eazycar.top/api/knowledge/login \
  -H 'Content-Type: application/json' -d '{"username":"shengwei","password":"wrong"}'

# 3. 对口令 → 200 + Set-Cookie
curl -i -c /tmp/kb-cookie.txt -X POST https://knowledge.eazycar.top/api/knowledge/login \
  -H 'Content-Type: application/json' -d '{"username":"shengwei","password":"123456"}'

# 4. 带 cookie 访问 → 200(登录态生效)
curl -b /tmp/kb-cookie.txt https://knowledge.eazycar.top/api/knowledge/stats

# 5. 其他路径 → 404(刻意)
curl -i https://knowledge.eazycar.top/api/messages
```

浏览器打开 `https://knowledge.eazycar.top/admin` → 登录框 → 输入账号口令 → 进入管理页。

## 五、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 打开 /admin 白屏或数据加载 404 | Nginx 只配了 `/admin` 没配 `/api/knowledge/`(或反之),两条都要 |
| 登录一直「失败次数过多」 | 确认 Nginx 传了 `X-Real-IP`;等 2 分钟自动解锁 |
| 全员被锁 | 服务重启即清零限流计数(内存实现);长期方案是确认没有人在爆破 |
| 会话经常掉 | 会话 7 天有效;改过 `KB_ADMIN_PASSWORD` 或 `FEISHU_APP_SECRET` 会使全部会话立即失效(设计如此),重新登录即可 |
| 访问 https://knowledge.eazycar.top/ 是 404 | 正常,只有 /admin 和 /api/knowledge/ 开放 |
| 知识库检索只有「关键词」没有「向量」 | `EMBEDDING_API_KEY` 未配置或失效,或启动自检失败(看启动日志);纯关键词模式功能仍完整 |
| 换了嵌入模型(EMBEDDING_MODEL/DIM) | 重启即可:旧文档自动标「待重建」并重建;管理页也可手动点「重建」 |
